# ScarletPico Color 2.2.1 — отдельный эксперимент DMA-видеовывода

Для существующей **RP2040-Zero, ST7796 480×320, MAX98357A**. Перепайка и
вторая Pico не нужны. База — v2.2.1 с новым стартовым звуком.

## Реальный замер до изменения

2026-09-28, пользователь запустил Zelda: Link's Awakening. Прочитан USB CDC
`/dev/cu.usbmodem101` в течение 20 секунд, без перезапуска/перепрошивки.
Получено 20 строк `PERF FIT HEIGHT 356X320`:

- EMU: **59**, LCD: **19** во всех этих строках.
- CPU/frame: **11 567–11 686 мкс**.
- LCD/frame: **48 472–48 580 мкс**.
- Это реальные сообщения работающей прошивки, а не замеры симулятора.
- Частота CPU в этих строках не указана; название базовой сборки предполагает
  200 МГц, но пользовательский выбранный профиль этим логом не подтверждён.

Таким образом, в измеренной сцене медленнее именно видеовывод. LCD/frame
включает работу видеодрайвера, не только передачу байтов. Этот лог сам по себе
не доказывает, какая часть 48,5 мс уходит на SPI, масштабирование или сравнение.

Для полностью изменившегося изображения 356×320 в RGB565 требуется 227 840
байт. При фактическом SPI 50 МГц только данные занимают минимум **36,4544 мс**,
теоретический предел — **27,43 полных обновления/с** без дополнительных затрат.
Поэтому DMA не обещает 60 FPS при изменении всего кадра. В сценах с небольшими
изменениями прежняя система частичных обновлений может передавать меньше.

## Что изменено

Два вызова побайтного `spi_write_blocking` в исходном `present_region` заменены
на передачу строк через аппаратный DMA. Данные, размер/положение изображения,
масштабирование, поиск изменившихся областей и расписание кадров не меняются.
Короткие строки менее 32 байт передаются прежним путём. Нет изменений CPU,
напряжения, SPI, цвета, интерфейса или игрового звука.

Выделяется один свободный канал через прежний SDK allocator, без жёсткого
номера: каналы SD и I2S не задеваются. Канал повторно используется до отключения
питания, не выделяется заново для каждого запуска игры. Если свободного
канала нет — старый путь без DMA. Перед возвратом ожидается окончание не
только DMA, но и сдвига последних пикселей SPI; приёмный FIFO очищается.
Чтение microSD по-прежнему ждёт освобождения общего SPI.

Добавлено **248 байт кода/констант и 8 байт статической RAM**. Пять точечных
изменений в базе — два вызова, две границы RAM, метаданные конца прошивки.
Игровое ядро, main, видеопоток, аудио, UI и прежние features побайтно сохранены.
Номер в «Об устройстве» пока остаётся 2.2.1: DMA-вариант — отдельный тестовый
файл, а не объявленная стабильная версия.

## Проверки и ограничения

`tests/test_video_dma_arm.py` исполняет ARM-код нового драйвера и исходного
рендера: точное совпадение всех пикселей, полные/частичные окна во всех размерах,
оба места подключения, повторяющиеся строки, порядок байтов, невыровненный
буфер, исчерпание каналов, восстановление SPI и сохранение IRQ других каналов.
Время и DMA моделируются: это **не измерение выигрыша FPS на устройстве**.

Ни текущая игра на консоли, ни microSD этим экспериментом автоматически не
изменялись. Физическая стабильность и эффект требуют сравнения на той же
сцене. Обработка аппаратного зависания сохраняет прежний видеоконтроль и
watchdog; новая схема не является независимым исправлением аппаратных сбоев.

## Как сравнить

1. Сохранить прогресс через меню паузы и выйти в список игр.
2. Выключить/подключить плату с BOOT и скопировать
   `02-video-dma-TEST.uf2` на **RPI-RP2** (не на microSD).
3. Выбрать прежнюю частоту CPU, запустить ту же Zelda, загрузить то же
   сохранение и сравнить движение в том же месте. Оставить USB для логов.
4. Проверить изображение, звук, паузу/снимок и несколько выходов/запусков игры.
5. Для отката — `01-v2_2-USER-TESTED-ROLLBACK.uf2`. Для нового стартового
   звука без DMA — `03-v2_2_1-CHIME-ONLY.uf2`.

Сборка: `python3 firmware/tools/build_video_dma_addon.py` после готовой v2.2.1.
Исходники — `video-dma-addon/video_dma.c`, отдельный сборщик и ARM-тест.
Исходная UF2 проверяется по SHA-256, все заменённые команды проверяются до
изменения; никакой полной пересборки старого несовпадающего `src/` нет.
