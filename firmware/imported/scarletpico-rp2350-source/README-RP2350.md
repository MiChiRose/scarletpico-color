# ScarletPico RP2350: экспериментальная прошивка

Это новая сборка **для Waveshare RP2350-Zero, Cortex-M33, flash 4 МБ**. Старый UF2 v0.9 использован для восстановления подключения и принципа работы. Его исходники не восстановлены: меню и аппаратная часть написаны заново, ядро GB/GBC взято из открытого проекта Peanut-GB с поддержкой Color.

**На приставке сборки ещё не проверены. 60 FPS не гарантированы.** Компиляция и проверки на компьютере завершены; результат для конкретного дисплея, проводов и игр нужно измерить.

## Что пробовать вечером

| Файл / вариант | CPU | SPI LCD | Изображение игры | Назначение |
|---|---:|---:|---:|---|
| A | 200 МГц | 50 МГц | 240×216 | Первый запуск: проверка распиновки, дисплея, SD и кнопок |
| B | 200 МГц | 100 МГц | 320×288 | Основной вариант: чёткое увеличение ×2, цель около 60 FPS |
| C | 240 МГц | 120 МГц | 320×288 | Максимальный эксперимент: дополнительный разгон CPU и SPI |
| D | 200 МГц | 100 МГц | 240×216 | Меньше данных для дисплея, если B не достигает нужной плавности |

Во всех вариантах дисплей физически остаётся 480×320. Указан размер игровой области; поля обновляются отдельно. Инициализация и меню используют примерно 12 МГц. Скорости в таблице относятся к игре и тесту LCD. Настройка периферийного тактирования позволяет получить именно 50/100/120 МГц в соответствующих сборках; показатель MHz рядом с игровым FPS показывает частоту, вычисленную драйвером SPI.

Повышенные скорости — эксперимент: спецификация ST7796S для последовательной записи не обещает работу на 50–120 МГц. Работоспособность зависит от модуля и проводов. Все CPU выше штатных 150 МГц RP2350 также являются разгоном. Напряжение ядра установлено 1,20 В. C — самый требовательный вариант; если возникают сбои, вернитесь к A или B.

Только передача полного изображения, без команд и подготовки, занимает:

| Вариант | Объём | Время передачи | Теоретический предел |
|---|---:|---:|---:|
| A | 103 680 байт | 16,59 мс | 60,28 FPS |
| B | 184 320 байт | 14,75 мс | 67,82 FPS |
| C | 184 320 байт | 12,29 мс | 81,38 FPS |
| D | 103 680 байт | 8,29 мс | 120,56 FPS |

Это расчёт пропускной способности, **не измеренные результаты**. Эмуляция ограничена примерно 59,73 кадра/с — штатной частотой GB/GBC. В A почти нет запаса для 60 кадров; его задача — первоначальная проверка подключения.

## Перед первой установкой

Установленной версии 1.0 на этом Mac нет. Сначала сохраните её **с самой приставки**, иначе файл v0.9 не позволит вернуть именно 1.0.

На этом Mac можно открыть `backup-current.command`, подключить приставку по USB с зажатой BOOTSEL и следовать подсказкам. Он только читает всю flash и проверяет копию; ничего не прошивает. Проверенную копию сохраните отдельно. Скрипт использует picotool из рабочей папки этой задачи, поэтому перенос одного скрипта на другой компьютер недостаточен.

После резервного копирования загрузите **A** обычным копированием UF2 на накопитель BOOTSEL. Это не требует перепаивать провода, если текущая распиновка совпадает с восстановленной ниже.

## Игры, управление и проверки

- Карта FAT32; игры `.gb` / `.gbc` в `/roms`. Подпапки поддерживаются. Если `/roms` отсутствует, открывается корень карты.
- Меню: UP/DOWN — выбор, A — открыть игру/папку, B — назад.
- В игре: удерживать **START+SELECT 0,7 секунды**, чтобы сохранить прогресс и выйти в меню. Затем можно выключить питание.
- Для отдельного теста экрана включите приставку с зажатым **SELECT**, отпустите кнопку после включения. SD для теста не нужна. Показываются красная/зелёная/синяя области и движущаяся белая полоса. B завершает тест.
- При тестировании игры оставьте её работающей 30–60 секунд. Запишите устойчивые **EMU**, **LCD** и **DROP**, затем повторите с B, C или D на той же сцене.
- LCD считает завершённые передачи изображения. EMU считает реально завершённые кадры эмуляции. DROP — число подготовленных кадров, заменённых более свежими за последний интервал. Первый интервал может показывать нули.
- Если появляются полосы, неверные цвета или зависания только на высокой скорости — сравните с A. Если проблема есть и на A, прежде всего нужно сверить подключение, ориентацию и инициализацию панели.

Полные кадры не синхронизированы с развёрткой панели через TE; возможен разрыв изображения даже при высоком LCD FPS. USB выдаёт диагностические строки через последовательный порт, но для обычной проверки достаточно показателей на экране.

## Восстановленное подключение

Здесь **GPIO**, а не номера ножек/контактов платы. Эти значения извлечены из v0.9; подключение текущего прототипа не проверено физически.

| Сигнал | GPIO |
|---|---:|
| SPI0 SCK, общий дисплей/SD | 6 |
| SPI0 MOSI, общий дисплей/SD | 7 |
| SPI0 MISO, SD | 4 |
| CS дисплея | 5 |
| DC дисплея | 8 |
| RESET дисплея | 9 |
| Подсветка, включается высоким уровнем | 10 |
| CS SD | 3 |
| A / B | 15 / 26 |
| SELECT / START | 28 / 27 |
| RIGHT / LEFT | 14 / 2 |
| UP / DOWN | 0 / 1 |

Кнопки замыкают GPIO на землю; используются внутренние подтяжки вверх. В программе SD и LCD не обращаются к общей шине одновременно. SD работает около 12 МГц, в 8-битном режиме; LCD передаёт пиксели в 16-битном режиме.

## Что изменено и что пока ограничено

Вывод переделан на DMA с 16-битными пикселями: не нужно отправлять каждый байт программным циклом или отдельно менять порядок байтов. Два буфера строк позволяют готовить следующую строку, пока передаётся предыдущая. Масштабирование использует заранее рассчитанные таблицы. Второе ядро выводит изображение, первое выполняет эмуляцию. Три буфера кадров не дают перезаписать кадр во время передачи; при отставании LCD выбирается свежий кадр.

Горячие функции эмуляции выполняются из RAM. Исправлено неопределённое поведение при автоматическом увеличении индексов палитр GBC. Большие чёрные поля не пересылаются каждый кадр. Счётчики обновляются раз в секунду.

Эта версия поддерживает GB и GBC через выбранное открытое ядро, но совместимость с вашими конкретными играми ещё не проверена. **Звук в этой тестовой версии отключён**: его подключение не удалось восстановить. Косметика и дополнительные функции версии 1.0 не перенесены.

Игры копируются с SD в область flash с адреса 512 КБ; предел ROM на штатной 4-МБ плате — около 3,5 МБ. Большие ROM не запускаются. Уже совпадающие блоки не переписываются. Прошивка занимает существенно меньше 512 КБ и не пересекает область ROM.

Новые сохранения находятся в `/scarlet2350/saves/<имя-ROM>.sav`, а предыдущая копия — `.sav.bak`. Старые `/saves` не перезаписываются и автоматически не импортируются. Сохранение выполняется при выходе в меню; выключение прямо в игре не сохраняет последние изменения. RTC MBC3 сохраняется при выходе и идёт во время игры; время выключенного питания не учитывается.

## Проверки перед выдачей

Четыре native-сборки RP2350, проверка их метаданных и структуры UF2, контроль размещения firmware/ROM и RAM. На компьютере выполнены по 120 кадров тестового оригинального ROM в режимах GB и GBC под AddressSanitizer/UndefinedBehaviorSanitizer. Проверены преобразование RGB555→RGB565, границы масштабирования, точное увеличение ×2 и оборачивание индексов палитры. Реальные SPI, SD, flash на плате, кнопки, загрузка коммерческих игр и FPS ещё не испытаны.

Исходники включены в архив вместе с файлами для повторной сборки. Это новая открытая основа, которую можно дальше исправлять по результатам вашей проверки.
