# ScarletPico Color — VIDEO16: отдельный тест видеовывода

**Обновление после испытания:** пользователь сообщил 23 LCD FPS, USB подтвердил
23 FPS и ~40,1 мс вместо ~49 мс. См. [следующий полноэкранный эксперимент](VIDEO-SHADOW-TEST.md).
Остальной текст ниже — исходная запись на момент подготовки VIDEO16.

2026-09-28. Для существующей RP2040-Zero, ST7796 480×320 и MAX98357A.
Без перепайки, второй платы, изменения частот или уменьшения изображения.
**Новая сборка подготовлена, но автоматически не загружена на консоль.**

## Что подтвердилось на устройстве

Пользователь сообщил, что предыдущий DMA8-тест не повысил FPS.
Повторное чтение USB-журнала без сброса устройства дало 15 строк:

- LCD 18–19, EMU 58–60;
- CPU/frame 11 947–16 010 мкс;
- LCD/frame 48 685–49 173 мкс.

Предыдущий замер был около 48,5 мс на видеовывод и LCD 19.
Таким образом, наблюдаемого улучшения нет. Прежний журнал не сообщает
фактическую частоту SPI, объём отправленных пикселей или точный идентификатор
UF2; нельзя приписывать все эти миллисекунды одной конкретной причине.

При фактических 50 МГц передача всех 356×320 пикселей RGB565 занимает минимум
36,4544 мс: 227 840 байт × 8 / 50 000 000. Даже идеальная передача не даёт
60 полных обновлений/с. Частичные обновления могут передавать намного меньше.

## Новый эксперимент

Предыдущий DMA8 заменял только передачу строки, оставляя последовательное
приготовление и ожидание каждой строки. VIDEO16:

1. Передаёт RGB565 16-битными словами SPI, восстанавливая прежние 8-битные
   команды после региона. Порядок байтов на проводе и цвета сохраняются.
2. Готовит следующую строку в другом буфере одновременно с отправкой текущей.
3. Не ждёт полного опустошения SPI между строками; перед возвратом из региона
   обязательно заканчивает DMA, дожидается SPI и освобождает шину для microSD.
4. Добавляет редкую диагностику в USB, без новых надписей на экране.

Не меняются ядро эмулятора, игровой APU, UI, алгоритм поиска изменившихся
регионов, расписание кадров, CPU/SPI/напряжение, полная высота 356×320 и полосы.
Из v2.2.2 включено только более длинное окончание стартового звука.
В «Об устройстве» номер 2.2.2 у обеих новых сборок; `VIDEO16` в USB отличает тест.

Один DMA-канал выделяется SDK, без фиксированного номера и без изменения IRQ
других каналов. Нет свободного канала — прежний рендер. При ошибке/таймауте
DMA выполняется остановка передачи и повторная отрисовка всего региона старым
драйвером; последующие регионы тоже используют старый путь. Прежний watchdog
сохранён. Это не гарантия защиты от любых аппаратных зависаний.

Цена: 1655 байт кода/констант, 56 байт статической RAM. Два буфера по 356
пикселей занимают 1424 байта стека core 1, а не дополнительный framebuffer.
В ARM-тесте наблюдалось 1904 байта стека при выделенных 4096; это не измерение
максимума на физическом устройстве с прерываниями.

## Файлы и сравнение

- `01-previous-DMA8-ROLLBACK.uf2` — предыдущий DMA8-тест, точный откат.
- `02-video16-TEST.uf2` — новый видеотест и удлинённый стартовый звук.
- `03-v2_2_2-LONG-CHIME-ONLY.uf2` — только длинный звук, исходный вывод без DMA.
- `04-v2_2-USER-TESTED-ROLLBACK.uf2` — более ранняя одобренная v2.2.

Сохранить игру, выйти в меню и через BOOT скопировать выбранный файл на RPI-RP2,
не на microSD. Игры и сохранения не удалять, карту не форматировать.
Для сравнения использовать ту же Zelda, ту же сцену и тот же профиль CPU.
Проверить движение, цвета, звук, паузу/снимки и несколько выходов в меню.
Оставить USB подключённым для чтения новых строк:

```text
VIDEO16 mode=... pixels=... regions=... total=... build=... spi=... path=...
```

- `mode`: 0 — полный вывод, 1 — проверка/вывод изменившихся областей.
- `pixels`, `regions`: переданные пиксели и число регионов последнего кадра.
- `total`: полное время видеоработы над последним кадром, мкс.
- `build`: время подготовки строк, мкс; пересекается с передачей и **не равно
  всему времени CPU**, не включает поиск изменений.
- `spi`: частота из текущих регистров и clock_get_hz, Гц.
- `path`: 0 — исходный путь либо кадр без передачи, 1 — DMA16,
  2 — ошибка DMA и повтор старым драйвером.

Это снимок последнего кадра, не среднее за секунду; прежняя строка PERF остаётся.
Диагностика читает согласованный снимок между ядрами и не печатает из core 1.

## Воспроизводимость

```sh
python3 firmware/tools/build_features_addon.py
python3 firmware/tools/build_video_fast_addon.py
python3 firmware/tools/package_video_fast_release.py
```

ARM GCC 14.3.Rel1, переменная `ARM_GCC_BIN`. Сборщик проверяет SHA базы v2.2.2,
все заменяемые команды и неизменность защищённых областей ядра/APU/UI/features.
Это сохранённые исходники дополнений поверх точной UF2, не полная пересборка
старого несовпадающего `src/`.

`tests/test_video_fast_arm.py` исполняет ARM-код нового транспорта и исходные
full/diff: точное совпадение пикселей для всех масштабов и частичных регионов,
порядок байтов, отсутствие записи в занятый DMA-буфер, SPI/IRQ, нехватка каналов,
таймаут/ошибка, нулевой вывод неизменного кадра и точная копия previous-buffer.
Полный features-прогон также выполнен на этой UF2. Логи включены в пакет.
**Эти проверки не измеряют физический FPS. Выигрыш VIDEO16 пока не подтверждён.**
