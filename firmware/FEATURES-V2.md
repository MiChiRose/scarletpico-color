# ScarletPico Color — experimental Features v2

Историческая инструкция v2. Текущая рабочая папка уже содержит дополнения
v2.1 и сборщик v2.1; точные исходники/сборщик v2 сохранены в
`source-features-v2-2026-09-28.tar.gz`. Старая UF2 и комплект для отката не изменены.

Target: the existing **RP2040-Zero / 2 MiB flash**, ST7796 480×320,
microSD on shared SPI0, MAX98357A on GP11/12/13. **Not an RP2350 UF2.**

## Что нового

- Настройки частоты: **125 / 170 / 200 МГц**, 200 по умолчанию. Выбор
  запоминается и применяется при следующем запуске игры. В меню — 125 МГц.
- **Start + Select, удерживать 1,5 секунды:** меню паузы. Отпустить кнопки.
- Пауза: продолжить, сохранить снимок, загрузить снимок, вернуться к списку игр.
  Крестовина — выбор, A — подтвердить, B — назад / продолжить.
- **Пять слотов на каждый ROM**, отдельно от обычного сохранения игры `.sav`.
  Перезапись занятого слота, загрузка и выход требуют подтверждения.
- Снимки хранятся в автоматически создаваемой папке `/states`. Каждый слот
  использует два чередующихся файла `.sps`: новый не перезаписывает последнюю
  проверенную исправную копию. При повреждении новой версии загрузчик пробует
  предыдущую. Не удалять вручную один из файлов пары как «дубликат».
- ROM больше прежнего лимита 1 568 768 байт: первые байты остаются в flash,
  остальные читаются с microSD через двухблочный кэш 4 КиБ. Максимальный
  разрешённый размер — 8 МиБ; ограничения поддерживаемых MBC и RAM остаются.

## Как сохранить точное место в Zelda

1. Удержать Start + Select, отпустить обе кнопки.
2. `Save state / Сохранить снимок` → выбрать слот → A.
3. Дождаться `State saved / Снимок сохранен`. После этого можно продолжить
   игру, выйти через меню паузы или выключить питание.
4. Позже запустить **тот же ROM**, открыть паузу → `Load state / Загрузить
   снимок` → свой слот → подтвердить A.

Выход в список игр **не создаёт снимок автоматически**. Обычный `.sav`
по-прежнему содержит только те данные, которые записывает сама игра.

Снимок включает весь картриджный RAM, а не один профиль Zelda. Загрузка старого
снимка может откатить и остальные профили, записанные внутри этой игры. При
последующем автосохранении / выходе восстановленный RAM попадёт в обычный `.sav`.
Для важных независимых прохождений хранить резервную копию папки `/saves`.

## Ограничения и безопасная проверка

- Это **экспериментальная сборка**. ARM-симулятор проверяет настоящий код,
  но не заменяет испытание проводов, карты, дисплея, питания и FPS на устройстве.
- 200 МГц сохраняет прежние запрошенные скорости LCD 50 МГц и SD 12,5 МГц.
  При 170/125 МГц делители SPI ограничивают фактическую скорость LCD примерно
  42,5/31,25 МГц; SD — примерно 12,14/12,5 МГц. Это расчёт делителей, не замер.
  Более низкая частота может заметно снизить LCD FPS.
- I2S заново рассчитывается из выбранной частоты при старте игры; целевые
  16 кГц звука и темп эмуляции не меняются. Синтезатор звука не переписан.
- Большие ROM могут давать задержки при промахах кэша. Эта функция устраняет
  ограничение вместимости flash, а не гарантирует прежний FPS для любой игры.
- Первый запуск большого ROM требует записи примерно 1,5 МиБ во flash и может
  занять время. Повторный запуск того же ROM использует проверку кэша.
- Поддержка больших ROM не добавляет поддержку новых типов картриджей и не
  увеличивает RAM RP2040. Некоторым играм по-прежнему может не хватить памяти.
- Не вынимать microSD и не выключать питание во время записи снимка или `.sav`.
  Две копии защищают от ряда неполных записей, **но FAT не защищена от любой
  внезапной потери питания**. Перед первым тестом скопировать `/saves` и `/states`.
- Снимки привязаны к этой версии структуры ядра/APU и идентичности ROM
  (размер + 28 байт заголовка). Это не переносимый формат других эмуляторов.
  Штатные `.sav` остаются в прежнем формате.
- После отката прежняя прошивка игнорирует `/states`; обычные `.sav` продолжат
  работать. Ранее слишком большие ROM снова будут недоступны.

## Установка и откат с Mac

1. Сохранить прогресс, выключить консоль. Не вытаскивать карту под питанием.
2. Зажать BOOT на RP2040-Zero и подключить USB к Mac; отпустить BOOT после
   появления диска **RPI-RP2**.
3. Скопировать `02-features-v2-EXPERIMENTAL.uf2` на RPI-RP2. Плата перезапустится.
4. Сначала проверить Zelda, паузу, запись и восстановление одного тестового
   слота. Проверить повторную загрузку после выключения/включения.
5. Затем проверить большой ROM и профили 170/125 МГц. Для привычного FPS
   вернуться к 200 МГц и перезапустить игру.

Для отката повторить BOOT-процедуру с `01-fastload-ROLLBACK.uf2`.
UF2 копируется **на RPI-RP2, не на microSD**. Карта при этом может оставаться в
консоли. Автоматическая прошивка устройства сборщиком не выполняется.

## Честно об исходниках и воспроизводимости

Рабочая версия создана поверх сохранённой, SHA-256-проверенной UF2 v0.9-B.
`src/` — более ранний/другой снимок основного проекта: его полная CMake-сборка
**не является побитовым восстановлением пользовательской рабочей прошивки**.

Для воспроизведения текущей версии нужны:

- `releases/scarletpico-v0_9-B-200mhz-lcd50-sd12-ui-v1-fastload.uf2` — точная база;
- `features-addon/` — весь новый C/ASM-код и карта импортов;
- `tools/build_features_addon.py`, `tools/uf2_audio_patch.py`;
- локальные заголовки в `vendor/Peanut-GB-CGB`, `vendor/pico-fatfs-sd`, `ui-addon`;
- Python 3 и Arm GNU Toolchain **14.3.Rel1** (`arm-none-eabi-gcc`).

```sh
ARM_GCC_BIN=/path/to/arm-gnu/bin python3 firmware/tools/build_features_addon.py
```

Сборщик не зависит от старых абсолютных путей CMake/Ninja. Он проверяет SHA базы,
все точки подключения и побитовую неизменность ядра, игрового рендера и APU.
Любое отличие базы останавливает сборку. Результат: UF2 и JSON со всеми
изменёнными байтами. Настройки — сектор `0x7f000`, ROM-кэш — с `0x80000`:
прошивка эти области не перекрывает.

Сохранены также исходники/базовые UF2 предыдущих дополнений:
`audio-addon/`, `ui-addon/`, `loader-addon/`, `tools/`, а также SDK и лицензии.
Это воспроизводимая **цепочка сборки с бинарной базой**, не заявление о наличии
полностью совпадающего исходного кода каждой инструкции исходной UF2.

## Проверки

`tests/test_features_arm.py` исполняет итоговый Thumb-код в Unicorn. Файловая
система, физический SPI/DMA и PLL аппаратно моделируются заглушками.

- Настройки RU/EN, перерисовка только строк, совместимость старой записи настроек.
- Реальный расчёт PLL для 125/170/200 и делителя I2S; порядок смены напряжения.
- Оригинальная логика эмулятора Zelda: снимок → действия → восстановление →
  повтор действий, совпадение состояния CPU/памяти/APU и PCM.
- Пять слотов, две версии, CRC, повреждение/обрыв записи, ошибки sync/close/read,
  нехватка памяти; без частичного изменения живой игры.
- Настоящие локальные Pokémon Silver, Crystal и Wario Land 3 по 2 МиБ:
  запуск ядра и восстановление, без распространения ROM в комплекте.
- Границы flash, большой ROM, промахи/попадания кэша, повторный запуск, очистка FIL.
- Ассемблерный вход паузы, отпускание кнопок, возобновление и чистый выход через
  прежний обработчик, а не через искусственную ошибку эмулятора.

Журнал тестов и ARM ELF/disassembly сохранены в `build-features-addon/`.
Для тестов нужны Python-пакеты `unicorn`, `capstone`, `pyelftools`, предыдущие
ELF в `build-audio-addon/`, `build-ui-addon/` и `build-loader-addon/patched.bin`.
Они включены в полную резервную копию проекта. Локальные ROM не включены;
для прогонов необходимо указать/разместить свои законно полученные файлы.
