# ScarletPico 2.2.4 — контроль аккумулятора, тест RP2040

Файл прошивки: `ScarletPico-v2_2_4-RP2040-BATTERY-TEST.uf2`.
Это отдельный тестовый релиз на основе 2.2.3 для реально установленного RP2040.
Прошивка автоматически на приставку НЕ устанавливалась.

## Что добавлено

- Пять делений батареи, напряжение, статус TP4056 в шапке меню.
- Напряжение, статус и деления на левом чёрном поле во время игры.
- Settings → Battery / Charger: подробности, включение и отключение мониторинга.
- Состояния CHARGING, CHARGE DONE, IDLE/UNKNOWN, CHECK SIGNALS.
- Предупреждение LOW BATTERY / LOW - SAVE GAME. Само выключение не выполняется.
- Проверка неверного сигнала SENSOR CHECK вместо ложного уровня заряда.

Это не точный счётчик процентов/мА·ч. Деления оцениваются по напряжению и зависят
от нагрузки, зарядки и конкретного аккумулятора. Состояние окончания зарядки
берётся с отдельного сигнала TP4056 и не подменяет измеренное напряжение.

## Сначала проводка

По умолчанию мониторинг ВЫКЛЮЧЕН. Без дополнительных компонентов одна прошивка
не может узнать ни напряжение батареи, ни состояние спрятанных светодиодов.
На новой/старой конфигурации без расширения настроек будет MONITOR OFF.

Нужны вход GP29 с защищённым от подпитки выключенной платы делителем 2:1 и
два изолированных активных-низких сигнала на GP18/19. Не подключать аккумулятор
или точки светодиодов TP4056 прямо к GPIO.

Текущий выключатель стоит после повышающего преобразователя. Поэтому обычный
постоянно подключённый делитель сейчас НЕ подходит: нужна отдельная коммутация
его питания либо подходящая развязка. Схема входной стороны оптопар также требует
фото реального модуля. Подробный контракт и ограничения:
`docs/HARDWARE-BATTERY.md` в корне проекта (также включён в архив исходников).

Включать мониторинг в меню только ПОСЛЕ проверки и подключения схемы:
Settings → Battery / Charger → A → прочитать предупреждение → A.
Вернуться B в Settings, затем B для сохранения. A на странице батареи отключает
включённый мониторинг. Программное OFF не заменяет электрическую развязку.

Экран работает только при включённой приставке: зарядка выключенной консоли
не включает дисплей автоматически.

## Совместимость и установка

Копировать UF2 на загрузочный диск RPI-RP2 при удержании BOOT, как у 2.2.3.
Только для RP2040, не RP2350. При необходимости батарею безопасно отключить и
прошивать от USB; не замыкать разные источники питания вручную.

Неизменены ядро, LCD-драйвер, частоты, распиновка кнопок/экрана/звука, форматы
ROM и сохранений относительно 2.2.3. Сохранены ограничения: обычный ROM до 1 МиБ,
RAM картриджа до 32 КиБ, вывод 320 × 288 и фиксированная экспериментальная
частота CPU 200 МГц. Для перехода с 2.2.2 сначала прочитать ограничения 2.2.3:
старые снимки и пути сохранений отличаются, автоматического переноса нет.

Точный откат 2.2.3 находится в соседней папке:
`../2026-10-07-rp2040-native-menu/02-ScarletPico-v2_2_3-RP2040-NATIVE-TEST.uf2`.
Этот файл не менялся. Параметры громкости/яркости совместимы в обе стороны;
новое расширение мониторинга старой версией не используется.

## Проверки

Пройдены:

- Сборка Cortex-M0+ / ARMv6-M, проверка family ID UF2 e48bff56, стартового
  вектора, границ flash/settings и запаса SRAM.
- Сравнение контрольных сумм неизменённых ядра и LCD с аудитом 2.2.3.
- Тесты модели напряжения с AddressSanitizer / UndefinedBehaviorSanitizer:
  пересчёт ADC, статусы зарядки, неверные значения, фильтр и гистерезис.
- Тесты общего интерфейса с санитайзерами.
- Выполнение собранного ARM-кода в эмуляторе: меню, настройки и запись flash,
  пауза/выход, ABI снимков, аудио/DMA, владение двумя видеобуферами, GB/GBC.
- ARM-тесты мониторинга: OFF по умолчанию/при повреждении записи, реальный
  пересчёт напряжения, debounce, частота ADC, статус DONE без принудительных
  100%, неверный датчик, предупреждение и границы игрового индикатора.

Периферийные чтения в ARM-тестах подменены: это НЕ физическая проверка ADC,
электрической схемы, датчика, зарядки, FPS или установки на приставку.

## Пересборка

Из корня проекта, с установленными CMake/Ninja и Python:

```sh
python3 firmware/tools/build_battery_release.py --toolchain /path/to/arm-none-eabi-toolchain --pioasm-dir /path/to/pioasm/lib/cmake/pioasm
```

SDK по умолчанию `firmware/vendor/pico-sdk`, можно указать `--sdk`.
UF2 формируется из SDK BIN с обычным RP2040 family ID; заводская ROM не меняется.
Для тестов ARM нужны Python-пакеты unicorn и pyelftools:

```sh
python3 firmware/tests/test_rp2350_menu_arm.py --rp2040 --elf firmware/build-rp2040-battery/scarlet2040.elf --battery
```
